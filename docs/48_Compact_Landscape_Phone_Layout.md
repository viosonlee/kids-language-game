# 横屏手机紧凑布局

> Author / Agent: Codex  
> Date: 2026-10-03  
> Scope: 横屏手机首页、场景、玩法、练习、反馈与发音诊断

本方案基于 docs/44、45、46 的布局修复增量补充，应用于本次源码构建；公开发行版尚未更新。

## 问题依据

此前连接的 PJE110 手机为 Android 16，物理分辨率 2780×1264（横屏），density 560，约 794×361dp，字体缩放 1.0。真实应用截图显示首页仍采用 340dp 兔子、80dp 顶部留白和大语言卡片，造成裁切与大范围滚动。此前仅用 960×600dp 检查不足以覆盖这类手机。

此前已安装 platform-tools 37.0.1，使用覆盖安装将 debug 包由 1.0.0/code 1 升至 1.0.2/code 3，没有清除应用数据。升级前 preferences 文件已备份到本地 build/device-review；升级后数据逐项核对未完成。用户本次明确断开手机并要求依据现有屏幕信息修复，因此本次修复包尚未安装或通过真机验收。没有安装或启动模拟器。

## 布局规则

- 横屏且窗口配置高度低于 480dp 时启用紧凑布局，不修改全局 density 或系统字体缩放。
- 首页边距 12dp、兔子 160dp，语言卡片按可用宽度排列，默认字体下三种语言和开始按钮同时可见。
- 场景卡片最小高度 112dp，默认字体下四个内置场景同屏；玩法按钮最小高度 64dp。
- 跟读页头部按钮 48dp、录音核心 80dp，提示内容使用剩余高度并可滚动；图片、文字、录音区互不覆盖。
- 选图页卡片最小高度 112dp，手动下一题独立保留 64dp 底部空间。
- 反馈与完成页缩小装饰图和标题，保留完整按钮；反馈遮罩仍覆盖整个页面。
- 发音诊断的详情区独立纵向滚动，录音与尝试次数控件在宽度不足时换行排列；结果面板不再依赖可能为零的剩余高度。
- 平板继续使用原有尺寸；居中文字明确占据可用宽度，诊断滚动改善也适用于平板。

## 验证与证据

新增 794×361dp Robolectric Native 图形回归（本机测试，不是 Android 模拟器）：

1. 首页三语言、兔子和开始按钮；场景至玩法至跟读；录音、成功反馈、完成返回；选图及手动下一题。
2. 真实 AssetContentRepository 的四个中文场景标题完整显示。
3. 发音诊断录音按钮与结果面板能够滚动到达。

主流程测试使用可控语音与音频实现，并不代表真实识别率验证。另修复旧测试在识别回调触发后尚未重组就检查麦克风状态的竞态，等待节点更新后仍断言其禁用。

渲染证据位于 [assets/48_Phone_Layout](assets/48_Phone_Layout/)。首页、玩法、跟读、成功反馈、选图下一题、完成及诊断截图由测试生成；跟读与选图使用测试题目。场景截图来自内置真实内容。所有截图均为关闭动画时的布局证据，不能替代 OEM 字体、挖孔安全区、动态动画或真机触摸验收。

本次没有修改 ASR 模型、阈值或超时，也没有实现新的兔子角色动画。超大字体或更窄窗口继续通过滚动访问内容，不承诺所有内容同屏；竖屏 UI 未在本次重新设计。

最终验证：`test assembleDebug lintDebug --offline` 成功（JDK 21，现有 debug keystore 签名）；Debug 178 + Release 150 = 328 个测试全部通过。Lint 无错误，13 个 Warning、2 个 Information。修复后的 APK 为 `app/build/outputs/apk/debug/app-debug.apk`，应用版本仍为 1.0.2/code 3，不替换 `build/update-release/` 或公开发布文件。
