## 测量与处理

从三个 items JSON 解析实际引用的全部 126 条 MP3，使用 FFmpeg loudnorm 的输入测量取得整体响度与真峰值。原素材跨语言范围为 -24.18～-15.15 LUFS，跨度 9.03 LU；94 条超出 -20 LUFS ±1 LU。仅检查文件存在无法发现这种音量差异。

本批选择 -20 LUFS、允许 ±1 LU、真峰值不超过 -1.5 dBTP，作为项目基本一致性门限。这是实现 FR-AUDIO-002 的工程目标，不是原 PRD 已指定的数值，也不能代表每台设备上的安全或舒适音量。

处理使用逐文件固定增益，不使用限幅、动态压缩、裁剪、变速或变调。保留输入采样率和声道，以 MP3 96 kbps 编码；输出测量合格、时长差不超过 0.1 秒且采样率/声道一致后，才替换该文件。预计峰值无足够余量则报错，不自动引入另一种声音处理。单个输出失败保留其原文件；整批不是跨文件事务，命令失败时应查看报告和 Git 差异。

本轮共调整 121 条，另 5 条保留原二进制。最终范围：

| 语言 | 数量 | 原始 LUFS 范围 | 最终 LUFS 范围 | 最终最高真峰值 dBTP |
| --- | ---: | --- | --- | ---: |
| 日语 | 62 | -20.96～-15.15 | -20.47～-20.38 | -4.25 |
| 中文 | 32 | -24.18～-17.52 | -20.48～-19.83 | -4.90 |
| 英语 | 32 | -21.89～-18.18 | -20.48～-19.88 | -3.23 |

最终整体跨度 0.65 LU。126 条输出的容器时长均与输入相同，采样率和声道检查通过。素材路径、题目文本和条目数量保持不变；内容 manifest 从 1.0.1 升为 1.0.2。

## 工具与后续生成流程

新增 scripts/check_audio_quality.py，默认只读检查内容文件实际引用的语音，拒绝目录逃逸、缺失资源、静音/不可测量输入和异常输出。报告包含每条输入/输出的 SHA-256、响度、真峰值、时长、采样率和声道，以及 FFmpeg 版本。报告路径必须位于资产目录之外。

```powershell
# 只读审核；不合格或测量失败返回非零退出码
python scripts/check_audio_quality.py --report build/audio-audit/current.json

# 重新生成语音后，对不达标文件应用已验证的固定增益
python scripts/check_audio_quality.py --normalize --report build/audio-audit/normalized.json
```

最终工具对已在门限内的文件直接保留，避免反复执行造成多代有损编码。本轮首次处理后再次执行 --normalize，126 条 SHA-256 均未变化。生成器产出的新语音应先运行归一化，再运行只读审核；CI 新增 FFmpeg 安装与只读响度检查，并上传 JSON 报告，CI 不自动修改素材。

## 剩余边界

本批仅处理 Item 示范语音。泡泡反馈、人声引导、音效和背景音乐不属于此门限的输入集合，docs/39 记录的逐题反馈过长仍未修复。固定增益与数值检查不能证明语言发音正确、压缩无可闻影响、目标设备音量合适或儿童容易模仿，仍需 FR-AUDIO-003 的听感与设备验收。

应用版本仍为 1.0.2 / code 3，公开发布版本仍未替换，本批未安装到设备。ASR 参数保持调查范围，图片/动效/平板布局、真实设备生命周期、升级保留数据及儿童观察继续处理；总目标未完成。
