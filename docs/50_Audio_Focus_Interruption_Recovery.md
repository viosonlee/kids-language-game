# 音频焦点中断与练习恢复

> Author / Agent: Codex  
> Date: 2026-10-03  
> Scope: 增量补充 docs/15、33、41、49；提示音频、跟读与选图状态机

## 审查发现

对照 docs/15 的音频焦点约定、PRD FR-SPEAK-002/003 与 FR-AUDIO-004，发现：

1. AndroidPromptPlayer 调用 requestAudioFocus 后忽略返回值。系统拒绝焦点时仍可能创建播放器或调用 TTS。
2. 焦点丢失事件调用 gate.complete，调用方无法区分“播完”和“中断”。跟读启用自动录音时会把截断提示当作已听完；鼓励被打断时可能自动进入下一题。
3. 无预录音频而等待 TTS 初始化时，原先仅等待初始化信号。失去焦点或 stop 不会立即结束该等待，存在迟到初始化后调用 speak 的路径。

上述为源码与可控制事件测试证据，不代表已完成 OEM 通话场景验收。

## 修改行为

- 仅 AUDIOFOCUS_REQUEST_GRANTED 才进入播放；拒绝/延迟授权及丢失焦点使用专门的 AudioPlaybackInterruptedException。它属于取消类型，避免首页、完成页的可选声音被中断时产生未处理异常。
- 票据隔离旧焦点回调。旧播放焦点变化不能取消新播放，当前中断仍会释放播放器并归还焦点。
- TTS 初始化等待同时监听票据取消；初始化成功后还检查票据有效性，中断后不会迟到开口。
- 跟读提示中断后进入可手动重播/录音状态，不触发自动录音；选图提示中断后仍可重播和选择。
- 成功鼓励中断后保留已记录的通过结果，只将本题切换为手动下一题；不重复计分，也不修改家长持久化的自动下一题偏好。跟读恢复应用后仍保留手动等待，进入新题时重新读取偏好。
- 重试鼓励中断后停止自动重播链，解除反馈占用，允许儿童主动重播或再次尝试。
- 发音诊断显示“播放被其他音频打断，请点击重播”。页面已取消时不再写回状态。

## 回归覆盖

AndroidPromptPlayerTest 增加 API 29 Robolectric 事件测试：系统拒绝焦点不创建播放器；准备中焦点丢失立即释放且迟到准备回调无效；旧焦点事件不能打断新音频、当前焦点丢失可以；等待 TTS 时中断立即结束而不是等初始化超时。

RepeatViewModelTest 与 ChooseViewModelTest 各增加三项状态机测试：提示中断后恢复；成功中断后保留结果并手动下一题；重试中断后不循环播放且可再次作答。跟读成功用例还覆盖 stop/loadSession 恢复，确认不会因重新读取 autoNext=true 而跳过手动等待。

定向验证已通过。最终全量结果见下方追加记录与 WORKLOG。

## 限制

未连接真机、安装模拟器、调整 ASR 模型/阈值/超时或公开发布版本。Robolectric 验证的是系统回调处理和状态机，不证明实际来电、OEM 焦点策略、SoundPool 短音效的听感或儿童观察验收。当前采用中断后等待主动操作，而非系统焦点恢复后自动续播；避免儿童尚未准备好时自行进入录音或下一题。

最终验证：`test assembleDebug lintDebug --offline` 成功；Debug 194 + Release 166 = 360 测试通过，无失败、错误或跳过。已生成本地 debug APK；未安装和公开发布。
