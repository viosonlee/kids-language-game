# 跟读页空间分配与大字号长句

## 问题与实现

原跟读页用 Box 叠放顶部、中部和底部。中间内容通过固定 top=80dp、bottom=120dp 预留空间，而底部麦克风包含 130dp 核心和 32dp 外围区域，另有底部间距，因此中部保留区域不足以隔开底部控件。题目卡片没有滚动路径，长句或大字号会受中间区域高度限制。

改为 Column 中的实际顶部行、占用剩余高度的题目行、实际底部录音区域，题目行上下留间距。题目卡片内部可垂直滚动，文本保持完整排版，不靠缩小字体或省略号隐藏内容。无题目时用权重空白保持录音控件位置。录音状态、权限、识别、声音及反馈层逻辑保持原行为。

## 自动化验证

AppNavigationJourneyTest 增加真实导航/跟读页回归：960×600dp 横屏、1.5 倍字体缩放、中文长句和长假名，滚动到读音，检查 TextLayoutResult 无文字溢出、读音位于顶部喇叭以下和麦克风以上，滚回目标文本后点击录音验证响应。示例中中文与假名仅用于同时施加两种文字布局压力，不作为真实双语题库内容。

默认 Robolectric 简化字体模式把整句假名测为 26px 宽，无法作为文字排版证据；本用例单独启用 GraphicsMode.NATIVE。原生模式的新布局定向通过，同一用例在旧生产布局上失败于滚动操作，随后恢复新布局。首次测试代码误把等待方法当成节点使用，已修正。测试截图的 PixelCopy 路径超时，改用原生 decorView.draw(Canvas) 保存渲染图；未修改布局断言或放宽超时来掩盖问题。

回归产生 `app/build/reports/ui/repeat-large-font.png`。这是 Robolectric 原生绘图预览，不是物理设备截图，不能证明设备字体、系统导航条、性能或完整页面视觉验收。全量命令及最终结果见本次 WORKLOG。
