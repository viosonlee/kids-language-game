# 首页语言卡片与大字号布局

> Author / Agent: Codex  
> Date: 2026-10-03  
> Status: 修复与原生渲染回归，真机验收待完成  
> Scope: 对 docs/03、docs/07、docs/33 的增量补充。

## 发现与实现

原首页语言卡片固定 170dp 宽并排显示。960×600dp、字体缩放 1.5 时，原生渲染图显示 Japanese 被拆为 Japanes 和 e，三张卡片高度不一致。此前初轮 hasVisualOverflow 报错不能单独作为裁切证据，后续通过正确节点与原生绘图重新核查；当前证据证明不自然断词，不将它夸大为整词消失。

首页语言区按可用宽度及字体缩放计算 1～3 列，基准最小宽度 160dp、间隔 8dp，行内卡片均分宽度，最后一行居中。语言区与设置失败提示可滚动，“开始练习”位于其外，固定保留可见位置；左侧兔子与介绍也提供滚动路径。顶部预留 80dp，与 64dp 家长入口分开。标准宽平板仍可三列，较窄或大字号布局按需换行；不改变语言选择或进入课程的行为。

使用普通 Column/Row 分行，避免为了简单三卡片布局依赖实验性 FlowRow API。没有改变字体或语言名称，也没有用省略号掩盖内容。

## 验证

真实 AppNavigationJourneyTest 新增首页原生 GraphicsMode 测试：960×600dp、1.5 倍字号，三语言标签均可滚动到达；直接检查未合并文字节点的单行、完整字符、不省略与文字行边界，允许最多 1px 像素取整误差。英文主副标题相同，分别检查两个节点，避免只匹配到其中一个。每次滚动都检查开始按钮可见，最后点击并验证进入场景页。

初轮错误匹配卡片合并语义，拿到国旗测量结果；改未合并节点后，又发现 TextLayoutResult 的段落框可为 192px 而文字自身仅 117px，hasVisualOverflow 不等价于实际文字越界。因此改为检查真实文字行边缘和字符范围，没有降低单行和完整性要求。

新布局定向测试通过；恢复旧生产页面运行同一最终测试，失败于无滚动父节点。已分别查看旧/新原生渲染图，旧图显示 Japanese 不自然断词，新图显示语言名称完整，开始按钮与语言滚动区域分离。测试内采用与 docs/44 相同的原生 decorView.draw 预览，不使用外部示意图替代实现。

预览输出：`app/build/reports/ui/home-large-font-initial.png`（初始位置）及 `home-large-font.png`（逐项滚动后）。旧页面对比图 `home-large-font-baseline.png` 是本轮临时验证输出，不在常规测试中生成。这些是 Robolectric 渲染，不是物理平板截图。最终全量验证见 WORKLOG。

## 边界

大字号下第三种语言可能需滚动才能完整查看；开始按钮始终保持独立可见。幼儿是否容易发现滚动、图标语义、目标设备字体/安全区、其他窗口尺寸仍需验收。本批未增加手机竖屏布局，未安装/发布 APK，ASR 与角色动作素材范围保持原状态，总审查目标继续。
