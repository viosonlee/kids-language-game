本方案基于 docs/20、docs/36～38 增量补充，替代“先清 Room，再写 DataStore 旧累计”的重置方式，自本次提交起生效。历史文档与 schema v1 保留。

## 原来的中断窗口

清空原先包含两个独立提交：Room 删除练习事件与逐题汇总，然后 DataStore 把 completed_count 写成零。异常提示只能说明当前进程的部分完成状态；如果两步之间进程退出，下次启动仍会把旧累计加入统计。即使重试，重新全量清空也可能删掉其间新增的练习。

## 迁移与重置协议

Room schema 升为 v2，新增 legacy_progress 单行表；显式 MIGRATION_1_2 只创建该表，保留已有事件、汇总和索引，不使用破坏性迁移。AppContainer 注册迁移，导出 2.json，1.json 未修改。

首次订阅累计统计时，仓库检查 id=0 行。不存在才从 DataStore 直接读取旧累计并插入；存在就只使用 Room。迁移读取不经过设置的临时默认值与错误恢复映射，读取/字段类型错误会传播至统计恢复提示，没有获得可靠值时不会持久化假零。不存在的旧键表示零，负值按零处理。只有一项无日期、无语言的历史计数，不虚构逐题明细。

导入使用 INSERT IGNORE。行的存在同时表示迁移完成，即使值为零也保留。一次成功导入后重新订阅或重开数据库不会再读旧键；另一个仓库实例持有迟到的旧值，也不能覆盖已经导入或清空的行。

重置在同一个 Room 事务中删除 practice_attempt、item_progress，并把 legacy_progress 的单行值写成零。任一步失败则三者一起回滚。尚未导入时也能直接重置，不要求先读取设置。重置提交后保留零值行，阻止下次启动重新导入旧累计；其后的新练习正常保存，不需要启动时自动重做一次全量删除。现有写入/清空排队和家长二次确认保持不变。

旧 DataStore completed_count 保留为只读迁移输入，不再属于当前统计或设置模型；本方案没有声称物理擦除此旧键。迁移标记与计数都以 Room 为准，当前清空不依赖再次写 DataStore。移除原来已无生产调用的增量/重置旧计数接口；旧键类型异常也不会阻断其他学习偏好的读取。本方案不支持主动降级到旧应用后继续使用旧存储逻辑。

家长页总完成数从同一条 Room 查询中的 completed 与 legacyCompleted 相加，使用 Long 加法；今日与语言统计只计算真实事件。设置暂时不可读不会把已迁移累计当作不可用，迁移本身失败则通过现有统计重试入口恢复。

## 录音按钮与导航测试修正

全量回归暴露了跟读页的可点击状态缺口：加载或播放示范期间，麦克风看起来可点，但 ViewModel 会忽略该点击。BigMicButton 增加 enabled，加载、示范、评分、反馈和完成状态禁用并使用静止灰色外观；准备录音、可重试和正在录音时启用。录音中的停止操作继续可用，未改变 ASR 模型、参数、超时或评分规则。

新增受控模型加载用例：加载未完成时按钮禁用，触摸不会启动识别；完成加载后点击启动，进入通过反馈后再次禁用。导航测试等待可用麦克风再点击。完成页由 LaunchedEffect 异步导航，因此测试还会等待目的页出现，再操作“重玩/回主页”，保留原有记录、轮次与语音次数断言。docs/38 的一次通过不能替代这里补齐的就绪状态覆盖。

## 验证范围与结果

LegacyProgressMigrationTest 新增八项：

1. 从已提交的真实 v1 schema 创建带记录的磁盘数据库，升级到 v2；保留逐题、语言和事件统计，旧累计只导入一次，重开后无需再读源。
2. 旧源读取失败不提交零、不删除新记录，恢复后可重试。
3. SQLite 触发器使导入失败，重开后仍可正常导入。
4. 第三个重置写入失败时，两个 DELETE 与旧累计一起回滚；重开仍保持原数值，解除故障后可重置。
5. 首次导入前重置，随后新增练习并重开，旧累计不复活，新练习不被重删。
6. 两个仓库并发，迟到的迁移不能覆盖另一个仓库已提交的清空。
7. 取消迁移不留下完成标记，也不阻断后续清空。
8. 迁移使用原始偏好，拒绝错误类型或读取失败产生的假零；废弃计数键不会影响其他设置。

现有家长、仓库、设置和统计 UI 测试同步到单一进度来源。初次定向 21 项中，两个长名称磁盘测试遇到 Windows 原生 SQLite 打开路径失败；缩短测试名称后 21 项全部通过，未改数据断言。后续全量发现上述录音就绪与完成页异步导航问题，补齐实现/测试同步后再验证。

最终命令为 `test assembleDebug assembleDebugAndroidTest lintDebug --offline`，使用现有本机 JDK 21 与 Debug 签名配置。实际 XML：Debug 165 项、Release 144 项，无失败、错误或跳过；lint 0 errors、13 warnings、2 information。没有新增 suppression 或改写旧 schema。

这些测试执行真实 Room/SQLite 事务及磁盘关闭重开，但没有在设备上强杀进程、断电或执行覆盖安装；它们不能证明设备故障时的文件系统行为。SDK 仍缺 platform-tools，仪器测试包仅构建，未运行。当前 APK 未安装或发布。
