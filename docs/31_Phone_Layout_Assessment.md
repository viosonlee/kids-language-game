# 手机横竖屏适配评估

> Author / Agent: Codex
>
> Date: 2026-09-30
>
> Status: 方案评估，尚未实施全应用手机适配
>
> Scope: 响应用户对手机横屏、等比例缩放和竖屏 UI 的询问；补充现有平板设计，不覆盖原规范

## 结论

手机适配可行，主要工作在 Compose 页面布局。语音、题库、评分、学习记录和更新机制可继续共用。建议先支持手机横屏，再增加手机竖屏的响应式布局；无需复制一套业务代码。

| 路径 | 相对工作量 | 主要影响 |
| --- | --- | --- |
| 整个页面等比例缩放 | 初始改动少，体验风险高 | 字体、点击区域和兔子一起变小；系统大字体、长文字、不同宽高比仍可能截断 |
| 手机横屏紧凑布局 | 中等，三种方案中适合优先实施 | 调整高度分配、兔子和图片尺寸、间距、卡片排列，保留儿童主要按钮尺寸 |
| 手机竖屏响应式布局 | 中等偏高，高于横屏适配 | 首页、跟读和选图需要重排；增加方向策略与旋转时录音/会话验证 |

## 已确认的约束

- AndroidManifest 当前 `screenOrientation="sensorLandscape"`，应用只请求横屏；最低 Android 10，手机硬件类型本身没有被排除。
- 首页兔子固定 340dp，三张语言卡片各 170dp，且只占右侧 58% 宽度。手机上仅缩放兔子不能解决语言卡片溢出。
- 跟读主体预留顶部 80dp、底部 120dp，另有外边距、130dp 麦克风、110sp 图片符号和 280dp 兔子。较矮手机横屏需要重新分配空间。
- 分类、玩法选择和诊断页使用固定左右比例，缺少统一的紧凑屏幕策略。
- 本轮选图已增加按宽度/字体比例分行和滚动，完成页已有局部自适应；这些不等于完整手机验收。

## 建议布局

手机横屏保留左右布局，缩小装饰和留白；录音按钮进入侧边操作区以释放纵向空间。选图根据宽度显示单排或两排，操作区域保持可见。家长设置与诊断页允许滚动，避免把所有信息挤在一屏。

手机竖屏建议为：

- 首页：上方兔子，中部语言选择，下方开始按钮。
- 跟读：顶部进度，中部图片与目标文字，下方兔子反馈和固定录音操作区。
- 选图：顶部示范与进度，中部 2×2 或按数量变化的图片网格，下方小兔子反馈。
- 家长设置、更新和诊断：单列可滚动布局，关键按钮不随文字变高而被遮挡。

复用组件、设计颜色和业务状态，以实际窗口宽高决定布局；不要仅按像素分辨率或设备型号判断。允许图片和兔子缩放，核心点击区域与文字独立设定最小尺寸。竖屏支持还需要调整当前方向锁定，验证旋转不会重复计分、自动重录或重新播放已完成的反馈。

## 后续验收范围

使用代表性手机宽高、大字体、挖孔/手势区域检查首页、分类、玩法、跟读、选图、反馈弹层、完成页、家长页和诊断页。横竖屏切换及后台恢复时复核录音停止、题目进度、提示播放和更新下载。保留平板横屏回归。
